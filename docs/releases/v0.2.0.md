# Release Notes: v0.2.0

## Status

Educational documentation release.

This release completes the FR-004 kernel contract catalog and deepens framework adapter blueprints for Node.js/TypeScript, Laravel, .NET, and Go. It is still documentation-first: no runnable application, package publish, or deployable runtime is included.

## Docs

Included since v0.1.0:

- kernel contract completion notes and README kernel list expansion;
- Node.js/TypeScript adapter blueprint;
- Laravel adapter blueprint;
- .NET adapter blueprint;
- Go adapter blueprint;
- changelog entries for the above.

## Contracts

Machine-readable contracts are unchanged from v0.1.0:

- [`contracts/openapi/public-api.v1.yml`](../../contracts/openapi/public-api.v1.yml)
- [`contracts/asyncapi/events.v1.yml`](../../contracts/asyncapi/events.v1.yml)
- [`contracts/json-schema/events/cloudevent-envelope.schema.json`](../../contracts/json-schema/events/cloudevent-envelope.schema.json)
- [`contracts/graphql/schema.graphql`](../../contracts/graphql/schema.graphql)

Kernel pseudocode contracts under `kernel/contracts/` now include event store, unit of work, specification, cache store, queue, and secret manager.

## Examples

Framework mapping is no longer a thin table only. Each stack guide now covers:

- module layout;
- kernel ports in the host language;
- composition root / module registration;
- feature slice walkthrough (`register-user`);
- HTTP and persistence adapter notes;
- queue/outbox and worker rules;
- boundary enforcement tooling;
- testing strategy, trade-offs, and common mistakes.

Stacks covered:

- Node.js/TypeScript;
- Laravel;
- .NET;
- Go.

## Security

Unchanged from v0.1.0 guidance and examples. Adapter blueprints reinforce:

- policy evaluation in features, not only middleware;
- runtime validation at untrusted boundaries;
- secrets kept out of domain code and logs;
- outbox/inbox and idempotent consumers.

Known security limitation:

- still guidance and examples, not an executable security test suite.

## Runtime

Runtime status:

- no runnable application is included;
- no package manager project is included;
- no Docker Compose file is included;
- no Kubernetes manifest is included;
- no Terraform or cloud deployment automation is included.

Runnable starter kits remain optional future work after this baseline.
