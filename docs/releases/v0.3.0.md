# Release Notes: v0.3.0

## Status

Educational documentation and runnable-skeleton release.

This release adds a Node.js/TypeScript runnable skeleton with reference modules and use cases on top of the v0.2.0 adapter blueprints.

## Docs

Included since v0.2.0:

- `starters/node-typescript` runnable skeleton README;
- changelog entries for the skeleton and modules.

## Contracts

Unchanged from v0.2.0. The skeleton implements kernel ports as TypeScript interfaces under `starters/node-typescript/src/kernel/ports.ts`.

## Examples

Runnable skeleton (`starters/node-typescript`) demonstrates:

- kernel ports and in-memory command/event/transaction adapters;
- identity `register-user` and `login` feature slices;
- access policy evaluator (role to permission);
- audit and notification modules as event subscribers;
- settings module with typed reader/writer used for login lockout;
- HTTP adapter with Problem Details errors and zod boundary validation;
- unit tests for handler, policy, settings, and lockout behavior.

## Security

- Policy evaluation is explicit in the register path (`identity.user.create`).
- Login publishes success/failure events and enforces `security.max_login_attempts`.
- Demo allow-list roles only; not a production IAM.

Known security limitation:

- still educational; password hashes are illustrative strings, tokens are opaque demo values.

## Runtime

Runnable status:

- Node.js/TypeScript skeleton runs with `npm install`, `npm test`, `npm run dev`;
- persistence is in-memory only;
- no Docker Compose, Kubernetes, or cloud deploy is included.

## Known Limitations

- One HTTP stack and language (Node.js/TypeScript).
- In-memory adapters only.
- Settings has no HTTP API yet.
- No outbox/queue workers yet.
- Other adapter blueprints (Laravel, .NET, Go) remain documentation.
